#+title: nix-hermes: Hermes AI Agent for NixOS/home-manager
#+author: Rafael
#+language: en

* Overview

A Nix flake wrapping [[https://github.com/NousResearch/hermes-agent][Nous Research's hermes-agent]] (v2026.8.27) with production-ready packaging for NixOS and home-manager.

** Packages

- =hermesFull= (also =default=): everything below — Chromium, Piper TTS, browser-use CLI, LSP servers, wake word, web dashboard, Electron desktop.
- =hermes-slim=: bare CLI + TUI only, straight from upstream — no browser, no voice, no LSP servers, no Chromium.
- =hermes-desktop-x11= / =hermes-desktop-wayland=: the packaged Electron app with =--ozone-platform= baked in.
- =hermes-desktop=: launcher that picks the right desktop variant at runtime (=WAYLAND_DISPLAY=/=XDG_SESSION_TYPE=).
- =ociImage=: an OCI/Docker image built from =hermesFull= (no Dockerfile — =pkgs.dockerTools.buildLayeredImage=), published as =rafadotel/hermes-agent= on Docker Hub.

** What =hermesFull= adds

- *Chromium* (local, on PATH) for browser automation
- *Piper TTS* (local, GPL-3, no API keys, no per-call network round-trips)
- *browser-use CLI* for autonomous browser control (attaches to running Chromium via CDP)
- *LSP servers* pre-baked on PATH: pyright, typescript-language-server, gopls, rust-analyzer, clangd, nixd
- *STT model* (faster-whisper "base") pre-fetched to avoid lazy downloads
- *Wake word* (sherpa) with exact pinned versions to avoid runtime dependency mismatches

** What it re-exports

- NixOS system module (=nixosModules.default=) — see [[*NixOS dashboard/gateway services][NixOS dashboard/gateway services]] below; this is a small module purpose-built for running the dashboard and/or gateway, not a full re-export of upstream's module
- home-manager module (=homeManagerModules.default=), unmodified from upstream
- Prebuilt Hermes CLI, TUI, web dashboard, ACP, and Electron desktop

Upstream's own Nix packaging (NousResearch/hermes-agent) handles the heavy lifting; this wrapper adds the missing pieces for production use.

* Quick Start

** NixOS system

Add to your flake.nix:

#+begin_src nix
{
  inputs = {
    nixpkgs.url = "github:nixos/nixpkgs/nixos-unstable";
    hermes-nix = {
      url = "github:rafa-dot-el/nix-hermes";
      inputs.nixpkgs.follows = "nixpkgs";
    };
  };

  outputs = { self, nixpkgs, hermes-nix }:
    let
      system = "x86_64-linux";
      pkgs = import nixpkgs { inherit system; };
    in
    {
      nixosConfigurations.myhost = nixpkgs.lib.nixosSystem {
        inherit system;
        modules = [
          ./hardware-configuration.nix
          hermes-nix.nixosModules.default
          {
            services.hermes-agent.dashboard.enable = true;
            # See "NixOS dashboard/gateway services" below for bindAddress/port/domain/auth/gateway.
          }
        ];
      };
    };
}
#+end_src

Then:

#+begin_src bash
nixos-rebuild switch --flake .#myhost
#+end_src

*** NixOS dashboard/gateway services

=services.hermes-agent= runs the web dashboard (=hermes dashboard=) and/or the messaging gateway (=hermes gateway=) as their own systemd services — always two separate processes, coordinating only through the shared =hermesHome=, never directly (verified against upstream's own module comments: the dashboard backend "does not run the messaging gateway... it does not contain a gateway"). This is a small, purpose-built module; upstream's fuller option surface (MCP servers, container mode, declarative config) is explicit future work, not available here yet.

Shared options live at =services.hermes-agent.*= (=package=, =user=/=group=, =stateDir=, =hermesHome=, and the =lsp=/=voice=/=browser=/=gateway= feature toggles below); everything dashboard-specific is under =services.hermes-agent.dashboard.*=, mirroring the split upstream uses between its shared options and its own =backend.*= sub-namespace. =package= defaults to a build with exactly the enabled features — the Electron desktop app is *never* included, regardless of the toggles below (neither service needs it, and skipping it avoids an unnecessary Electron/Chromium-for-Electron dependency closure on a headless host).

#+begin_src nix
{
  services.hermes-agent = {
    # hermesHome defaults to "${stateDir}/.hermes" — override to point it at
    # a separate volume. This is persistent application state (config.yaml,
    # sessions, memory, cron), not scratch/tmp. Shared between dashboard and
    # gateway when both are enabled — that's how they coordinate.
    hermesHome = "/var/lib/hermes-agent/.hermes";

    # Feature toggles for `package` — each true by default; set any to
    # false to shrink the closure (e.g. a gateway-only host with no browser
    # automation needed can set browser.enable = false).
    lsp.enable = true;
    voice.enable = true;
    browser.enable = true;

    gateway = {
      enable = true;  # also controls whether messaging/matrix extras are in `package`
      extraArgs = [ ];
    };

    dashboard = {
      enable = true;
      bindAddress = "0.0.0.0";  # default; only applies when `domain` is unset — see below
      port = 8080;              # default when `domain` is unset (unprivileged); 443 when it is — only nginx ever binds a privileged port
      openFirewall = true;

      # Optional: Let's Encrypt TLS via an nginx reverse proxy.
      domain = "hermes.example.com";

      # Optional: HTTP Basic Auth in front of it (requires `domain`).
      basicAuth = {
        enable = true;
        passwordFile = "/run/secrets/hermes-dashboard-htpasswd"; # htpasswd -c ...; never a Nix store path
      };

      # Optional: mutual TLS client-certificate verification (requires `domain`).
      # caFile is a CA cert (public, fine as a Nix store path) — can combine
      # with basicAuth, or use verifyOptional = true for cert-or-password.
      mTLS = {
        enable = true;
        caFile = ./my-client-ca.pem;
      };
    };
  };

  # Required by NixOS whenever any vhost has enableACME (not set for you —
  # accepting Let's Encrypt's subscriber agreement is your decision):
  security.acme.acceptTerms = true;
  security.acme.defaults.email = "you@example.com";
}
#+end_src

Without =domain=, the dashboard binds directly on =bindAddress=:=port= with no TLS layer — fine for a Tailscale/VPN-only setup, not for the open internet. Whenever =domain= *is* set, the dashboard process is always forced to =127.0.0.1= regardless of =bindAddress=, so the TLS+auth front door can't be bypassed on the local network.

PAM-based auth was considered and deliberately left out — it would need a custom nginx build plus giving the nginx worker access to a shadow-backed PAM stack, a materially larger attack surface than basicAuth/mTLS for a network-facing daemon. Left as explicit future work if actually needed.

** home-manager

Add to your home.nix:

#+begin_src nix
{
  imports = [
    # ... other imports
  ];

  inputs = {
    home-manager.url = "github:nix-community/home-manager";
    hermes-nix = {
      url = "github:rafa-dot-el/nix-hermes";
    };
  };

  home.packages = [
    inputs.hermes-nix.packages.${pkgs.system}.default
  ];

  imports = [
    inputs.hermes-nix.homeManagerModules.default
  ];
}
#+end_src

Or via standalone home-manager:

#+begin_src bash
# Add to ~/.config/home-manager/flake.nix inputs
hermes-nix.url = "github:rafa-dot-el/nix-hermes"

# In home.nix
imports = [ hermes-nix.homeManagerModules.default ];
home.packages = [ hermes-nix.packages.${system}.default ];

# Apply
home-manager switch --flake ~/.config/home-manager
#+end_src

* Configuration

** Piper TTS (local text-to-speech)

Edit your Hermes config.yaml:

#+begin_src yaml
tts:
  provider: piper
  piper:
    # Path to the bundled Piper voice model
    voice: /run/current-system/sw/share/hermes-agent/piper-voices/en_GB-alba-medium.onnx
#+end_src

No API key needed. Piper runs locally with zero network round-trips.

To use a different voice, download from [[https://huggingface.co/rhasspy/piper-voices][rhasspy/piper-voices]] and update the path.

** STT (speech-to-text)

By default, faster-whisper "base" is bundled. Configure in config.yaml:

#+begin_src yaml
stt:
  local:
    model: /run/current-system/sw/share/hermes-agent/faster-whisper-base
#+end_src

** Browser automation (browser-use + agent-browser)

The CLI has two browser backends:
- *browser-use*: Autonomous agent-driven browser control (requires Chromium running with --remote-debugging-port)
- *agent-browser*: Built-in browser toolset for hermes_agent (CDP-driven)

Both auto-detect Chromium on PATH (included in this package).

** Wake word (sherpa)

Configured via config.yaml:

#+begin_src yaml
wake_word:
  provider: sherpa
#+end_src

Default supports any phrase in English; no training needed.

* Docker Hub

=rafadotel/hermes-agent= on Docker Hub is =hermesFull= packaged as an OCI image (built via =pkgs.dockerTools.buildLayeredImage=, no Dockerfile). Currently =linux/amd64= only — =arm64= isn't wired into CI yet (see =task oci:push= below to publish one by hand from an aarch64 host).

#+begin_src bash
docker pull rafadotel/hermes-agent:latest
docker run --rm -it rafadotel/hermes-agent:latest
#+end_src

Tags: =latest= (tracks =main=) and a version tag per release (e.g. =2026.8.27=, matching the git tag without its leading "v").

* Building from source

If you prefer to build locally (or the cache is unavailable):

#+begin_src bash
nix build github:rafa-dot-el/nix-hermes#default --no-link   # hermesFull
nix build github:rafa-dot-el/nix-hermes#hermes-slim --no-link   # bare CLI+TUI
#+end_src

Or in a flake project with =hermes-nix= as an input:

#+begin_src bash
nix build .#hermes-nix.packages.${system}.default --no-link
#+end_src

Or with this repo checked out, via Task (see its own targets for the full local build/publish flow — =task build=, =task build:slim=, =task build:desktop=, =task oci:build=/=oci:push=, =task cache:push=, =task tag=/=task release=):

#+begin_src bash
task build
#+end_src

** Multi-architecture builds

Currently supported: x86_64-linux, aarch64-linux

#+begin_src bash
# Build for aarch64 on x86_64 (requires remote builder or native aarch64 system)
nix build --system aarch64-linux github:rafa-dot-el/nix-hermes#default
#+end_src

* Troubleshooting

** Piper TTS not found

Check that the voice path exists:

#+begin_src bash
ls -la /run/current-system/sw/share/hermes-agent/piper-voices/
#+end_src

If missing, verify Hermes is installed correctly and Nix cache is working.

** Browser automation not working

Ensure Chromium is on PATH:

#+begin_src bash
which chromium
#+end_src

If not found, verify the Hermes package is correctly installed with extraPathTools.

** LSP server not detected

Verify the server is on PATH:

#+begin_src bash
which pyright typescript-language-server gopls rust-analyzer clangd nixd
#+end_src

Configure in Hermes: =lsp.install_strategy: manual= in config.yaml.

** Build timeout or OOM

If building locally (without Cachix), the build is resource-intensive (~30 min on modern hardware, ~8GB RAM). Use the binary cache or increase system resources.
